# Authentic Product Representation

A product visual makes claims. Every claim must hold when someone tries the product.

## Keep it truthful

- **Show only real capabilities.** A demo of a feature the product doesn't have is a promise you break on first use.
- **Numbers reflect reality.** Stats, counts and metrics are real or clearly illustrative, never inflated fiction presented as fact.
- **Labels match content.** Don't caption a screenshot of system A as system B, or show a domain in the command that doesn't match the results.
- **Values match the input shown.** If the visual claims to process `yourdomain.com`, show what processing it yields, not another site's values relabelled.
- **Reproduce the real format** when a visual stands in for product output, such as a CLI run, report or generated file: the same labels, ordering and truncation. Take values from a real run where you can.
- **"Soon" means soon.** Don't put a pending badge on something that already ships, and prefer showing what works over what's planned.

## When you must stage

If a literal screenshot is impossible (pre-launch, sensitive data, a composite view), keep claims conservative and label illustrative figures as illustrative. Placeholder filler is fine where it makes no claim.

## Review

Could someone use the real product and get the outcome this visual shows? If not, change the visual.
